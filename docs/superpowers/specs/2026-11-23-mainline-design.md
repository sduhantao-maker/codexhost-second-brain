# 主线任务（Mainline）插件设计

> 0.10 起插件改名为「第二大脑 / Second Brain」（id `second-brain`），数据目录随之改为 `host-extension-data/second-brain/`，第一次启动时从旧目录复制数据；见 [v2 设计](2026-11-23-mainline-v2-design.md) §13。本文是 v1 的设计，正文保留当时的名字，下面标「0.10 起」的是现在的做法。

- 日期：2026-11-23
- 状态：已实现 0.2.3（含 4.9 PR 与 Issue 索引），本机试用中（实机验证后调整了胶囊默认位置与 Web 会话行识别，见 4.6、4.7）
- 0.8 的变化：文中「0.8 起」的注记是现在的做法；完整说明见 [v2 设计](2026-11-23-mainline-v2-design.md) §7、§9 和 §11。
- 插件 ID：`mainline`（0.10 起为 `second-brain`）；名称：主线任务 / Mainline（0.10 起为「第二大脑」/ Second Brain）

## 1. 要解决的问题

在多个窗口之间来回切换，注意力会被削弱，常见两种走偏：

1. **同一窗口串题**：在窗口里处理问题 A，看到新问题 B，下意识就在同一个窗口接着做了。
2. **一题多窗**：同一个问题开了好几个窗口，散在各处，记不清哪个窗口做到哪一步。

插件要在每个窗口内、也在窗口之间，持续提示「主线」：目标是什么，已经完成了什么，正在做什么。用户和 Agent 看到的是同一份记录，不会记错。

## 2. 已确认的决定

| 决定 | 结论 |
| --- | --- |
| 支持的界面 | 两边都做：官方 Codex Desktop（`desktop` 入口），以及 codexhost 自带窗口和 Web/PWA（`web` 入口）。 |
| 进度由谁维护 | Agent 自动维护。用户在插件里点「安装」后，才为 Claude Code 和 Codex 写入协作配置；安装前列出要改的文件和改动，可以随时卸载（0.8 起：点「卸载」，看过改动后再点「确认修改」）。 |
| 偏题时的默认做法 | 先问用户（设置里可改为「只记录不打断」或「关闭」）。 |
| 发布 | 先装在本机试用，用户确认没问题后再发布到插件市场。 |
| 代码位置 | `~/Code/codexhost-mainline` |

## 3. 概念

- **主线**：一个需要多步完成的目标。包含目标、已完成清单、支线待办、状态（进行中或已结束）。编号形如 `#k3f9`。
- **窗口**：codexhost 的一个对话（Thread）。一个窗口最多属于一条主线，一条主线可以挂多个窗口。
- **正在做**：每个窗口各记一条，说明这个窗口当前在做主线的哪一步。
- **偏题**：窗口里出现了与主线无关的新问题。偏题标记挂在窗口上，处理后清除。
- **支线待办**：暂时不做、先记下来的主线外问题，挂在主线上，不会丢。
- **委派继承**：从主线窗口委派出去、仍在工作中（运行中或等用户处理）的子窗口自动加入同一条主线；已经结束的旧委派不会被拉进来。用户把它移出后不再自动加入。

## 4. 架构

```text
Claude Code ── UserPromptSubmit hook ─┐
Codex ──────── AGENTS.md 说明 ────────┤
                                      ▼
                         bin/mainline（命令行）──读写──▶ state.json ◀──读写── backend（单实例 Node）
                                                                              ▲         │
                     desktop.js（Codex Desktop）── backend.invoke ────────────┤         │ 只读 HTTP
                     web/index.mjs（自带窗口/Web）── backend.invoke ──────────┤         ▼
                     page/index.mjs（总览页）───── backend.invoke ───────────┘   codexhost 本机接口
                                                                                 （标题、状态、子窗口）
```

插件包使用 `manifestVersion: 2`，声明四个入口：

| 入口 | 文件 | 职责 |
| --- | --- | --- |
| `desktop` | `desktop.js` | 在 Codex Desktop 主窗口识别当前窗口、显示主线胶囊、跳转窗口、把对话树上报给后台。 |
| `web` | `web/index.mjs`、`web/style.css` | 在自带窗口和 Web 里做同样的事，当前窗口从页面 DOM 识别。 |
| `page` | `page/index.mjs`、`page/style.css` | 「主线总览」页（0.10 起叫「第二大脑」），两端都能打开。 |
| `backend` | `backend/index.mjs` | 读写状态、查询对话标题和状态、发现委派子窗口、安装或卸载 Agent 协作。 |

另有 `bin/mainline.mjs`：给 Agent 用的命令行。后台每次激活时把它复制到数据目录下的固定路径。

不占用任何 Desktop 独占槽位，可以和「侧栏委派树」同时启用。

### 4.1 状态文件

位置：`$CODEXHOST_DATA_DIR/host-extension-data/mainline/state.json`（默认 `~/.codexhost/...`；0.10 起是 `host-extension-data/second-brain/state.json`）。

```ts
interface State {
  version: 1;
  rev: number; // 每次写入加一，前端据此判断是否需要刷新
  mainlines: Record<string, Mainline>;
  threads: Record<string, ThreadEntry>; // 键为 Thread ID
}
interface Mainline {
  id: string; // 4 位小写字母数字
  goal: string;
  status: "active" | "finished";
  createdAt: number;
  updatedAt: number;
  finishedAt?: number;
  done: Item[]; // 新的在后，最多 100 条，超出丢弃最旧的
  parked: Item[]; // 最多 50 条
}
interface Item { id: string; text: string; at: number; threadId?: string }
interface ThreadEntry {
  mainlineId?: string;
  detached?: boolean; // 用户主动移出，阻止委派继承
  via?: "agent" | "user" | "delegation";
  title?: string; // 最近一次看到的标题，供命令行和总览页使用
  parentId?: string; // 已知的委派父窗口
  doing?: { text: string; at: number };
  drift?: { text: string; at: number };
  lastPrompt?: { text: string; at: number }; // hook 记录的最近一条用户消息，截断到 300 字
  updatedAt: number;
}
```

- 文本统一去掉首尾空白，超过 300 字截断并加省略号。文件超过 1 MiB 时拒绝写入并报错。
- 写入：用 `mkdir state.lock` 加锁，每 25 ms 重试，最多等 2 秒；锁超过 10 秒视为残留并清除。写到临时文件后 `rename` 原子替换，`rev` 加一。0.8 审计后：锁里记着持有者，持有期间每 0.5 秒刷新一次时间；超过 10 秒没刷新、又 1.5 秒没有变化的锁才接管。接管和释放经过一个短暂的 `state.lock.guard` 逐个进行，接管前再确认还是同一把残留的锁，释放只删自己的锁，写入前再确认锁还是自己的。收藏、PR 索引、调用计数和附件归属的锁都是这一套。
- 读取不加锁。文件损坏时另存为 `state.corrupt-<时间>.json`，从空状态重新开始。0.8 审计后：每个数据文件都这样，在写入覆盖之前另存，每个文件最多留 3 份；版本比当前版本新的文件不改名也不覆盖，读写都报 `NEWER_VERSION`。
- 命令行和后台共用同一份存储代码。

### 4.2 命令行（Agent 协议）

后台激活时写入：

- `…/mainline/bin/mainline.mjs`：命令行本体。
- `…/mainline/bin/mainline`：POSIX 包装脚本。优先用后台运行时所在的 Node（激活时写入绝对路径），找不到再用 `PATH` 里的 `node`。
- `…/mainline/bin/mainline.cmd`：Windows 包装脚本。

当前窗口按顺序取：`--thread <id>`、`CODEXHOST_THREAD_ID`、`CODEX_THREAD_ID`。都没有时报错退出。

| 命令 | 作用 |
| --- | --- |
| `mainline show [--json]` | 打印本窗口的主线卡片和协作约定。0.8 起：第一次打印全文，之后打印一行状态，`--full` 打印全部；Codex 会话只有 `CODEX_THREAD_ID`、环境里没有其他 `CODEXHOST_*` 变量、codexhost 也不认识这个对话时，什么都不打印。 |
| `mainline new "<目标>"` | 新建主线，并把本窗口挂上去。 |
| `mainline goal "<目标>"` | 修改本窗口所属主线的目标。 |
| `mainline doing "<一句话>"` | 设置本窗口正在做的事。 |
| `mainline done "<一句话>"` | 在主线的已完成清单里加一条，记下是哪个窗口完成的。 |
| `mainline park "<一句话>"` | 把主线外的问题记入支线待办。 |
| `mainline drift "<一句话>"` / `--clear` | 标记或清除本窗口的偏题。 |
| `mainline join <编号>` / `mainline leave` | 把本窗口加入某条主线，或移出当前主线。 |
| `mainline list [--json]` | 列出进行中的主线。 |
| `mainline finish` | 结束本窗口所属的主线。 |
| `mainline hook claude-prompt` | 内部命令，供 Claude Code 的 hook 调用。 |

普通命令出错时向 stderr 写一行原因，退出码为 1。hook 模式无论发生什么都静默退出、退出码为 0，绝不阻塞用户发消息。

### 4.3 协作约定（协议文本）

协作约定只在命令行里生成，`show` 和 hook 输出同一份内容，并按偏题设置与窗口状态变化。语言跟随界面语言，默认中文。

0.8 起，全文不再每条消息都给。Claude Code 的 hook 在每个会话的第一条消息时给全文，之后每 30 条消息、超过 12 小时或约定变化（另一种偏题设置、插件新版本等）时再给；其间只在标题或状态、进度、当前里程碑、正在做的任务或未处理的引申问题数变化时给一行状态，没变化就什么都不加。`show` 同样先全文后状态行。给过什么记在数据目录的 `context/<对话>.<hook|show>.json`，只存指纹、时间和 Claude 会话编号，3 天没用就删掉。下面是 0.2 的文本，现在的文本见 v2 设计 §7。

本窗口已有主线时（偏题设置为「先问我」）：

```text
【主线任务】本窗口的主线：#k3f9「开发主线任务插件」（3 个窗口）
已完成：设计已确认；建立仓库（最近 3 条，共 5 条）
正在做（本窗口）：写后台存储
其他窗口：「跑测试」正在做：……
支线待办：修复侧栏图标错位
约定（命令 mainline = <绝对路径>）：
- 开始新的一步时运行 mainline doing "一句话"；完成一个可交付的步骤时运行 mainline done "一句话"。
- 如果这条消息开启了与主线无关的新问题（不是主线的子步骤、追问或修正）：先别动手，运行
  mainline drift "新问题一句话"，用一句话提醒用户并给三个选择：① 记入支线待办，稍后处理
  （mainline park）② 用户新开窗口处理 ③ 把本窗口主线改成新问题（mainline goal）。
  按用户的选择做完后运行 mainline drift --clear。
- 主线目标达成后，问用户是否结束这条主线（mainline finish）。
```

- 「只记录不打断」：照常处理，同时运行 `mainline park`，并在回复开头用一句话说明它不在主线上。
- 「关闭」：不写偏题规则。
- 本窗口还没有主线时：列出最多 8 条进行中的主线；约定改为「需要多步完成的任务，如果属于上面某条主线，先问用户要不要加入（`mainline join`），否则运行 `mainline new` 建立主线；闲聊或一两句能答完的问题不建主线」。

### 4.4 Agent 协作的安装与卸载

在总览页的「Agent 协作」区操作。安装前显示要修改的文件和具体改动，用户确认后才写入。

| Agent | 文件 | 改动 |
| --- | --- | --- |
| Claude Code | `~/.claude/settings.json` | 在 `hooks.UserPromptSubmit` 加一条 command hook：`"<…>/bin/mainline" hook claude-prompt`，超时 5 秒。每条用户消息都会带上本窗口的主线和协作约定（0.8 起：全文只在会话的第一条消息等时候给，其间只给变化的状态行，见 4.3）；不在 codexhost 会话里时不输出任何内容。 |
| Codex | `~/.codex/AGENTS.md` | 末尾追加一段由 `<!-- codexhost-mainline:start -->` 和 `<!-- codexhost-mainline:end -->` 包住的说明：在 codexhost 会话里，每次收到用户消息先运行 `mainline show`，按其中的约定执行。0.8 起只有一句：对话第一条消息时运行一次 `mainline show` 并照做（不在 codexhost 里时它什么都不打印）；装着旧段落时显示「需要更新」。 |

- 识别依据：hook 命令包含 `host-extension-data/mainline/bin/mainline`；AGENTS.md 中存在上述标记。0.10 起：hook 命令含 `hook claude-prompt` 且命令是 `bin/mainline`，标记仍是 `codexhost-mainline`，所以改名前装的 hook 和段落也认得出，显示「需要更新」。
- 每次写入前，把原文件备份到 `…/mainline/backups/`（0.10 起是 `…/second-brain/backups/`），不在用户的配置目录里留下备份文件。0.8 起：备份是完整副本，可能含登录凭据，所以权限是只有用户能读（旧备份也改过来）；每个文件最多留 3 份，超过 30 天的在下次备份时删掉。读不了的配置文件（权限不够等）不再当成不存在，显示不可用和原因，拒绝安装。
- 只增删属于本插件的那一条 hook 或那一段说明，不改动其他内容。`settings.json` 无法解析时拒绝修改并报错。
- 状态分为未安装、已安装、需要更新（命令路径或说明文本与当前版本不一致）。

### 4.5 后台

后台方法（前端通过 `backend.invoke` 调用）：

| 方法 | 作用 |
| --- | --- |
| `snapshot { rev? }` | `rev` 没变时只返回 `{ rev }`；变了返回完整状态、设置和对话信息。状态文件只在修改时间或大小变化时重新读取。v2 起参数和返回叫 `version`；0.8 起它由页面看得到的内容算出，不再跟文件签名走：状态（不含 `rev` 和后台任务记录）、PR 索引里显示的部分、对话信息的版本、全部设置、凝练进度和次数、收藏。只改了簿记（扫描进度、查询时间、通知时间）时版本不变，页面不重拉。 |
| `mutate { op, … }` | 界面上的编辑：新建主线、改目标、改正在做、增删已完成和支线、清除偏题、加入、移出、移动窗口、合并主线、结束、重新打开、删除。 |
| `focus { threadId, surface }` | 前端报告当前窗口；后台优先刷新它的标题、状态和子窗口。 |
| `reportTree { nodes, parents }` | Desktop 前端上报 `threads.watchTree` 的标题、状态和父子关系，节流到每 2 秒最多一次。 |
| `integration.status` / `integration.preview` / `integration.install` / `integration.uninstall` | Agent 协作的状态、预览、安装和卸载。 |

对话信息来源：

- Desktop 运行时，由 `desktop.js` 上报的对话树提供。
- 只开自带窗口或 Web 时，后台读取 `$CODEXHOST_DATA_DIR/cli-credentials.json`，调用 codexhost 本机接口的只读路由：`POST /v1/thread/read { threadId }` 取标题和状态，`POST /v1/thread/list { parentThreadId }` 找委派子窗口。结果缓存 15 秒。接口不可用时退回到状态文件里记录的标题，状态显示为未知。
- 0.8 起：标题、状态和 Agent 先由一次共用的 `/v1/thread/list`（最近更新的 50 个，最多 20 秒一次）回答。只有列表答不了的才单独 `read`：打开着的对话（最多 15 秒一次）、列表说在运行的（只有读才分得出是不是在等用户，1 分钟）、页面要显示却不在列表里的（5 分钟）。单独读排一个队，同时最多 2 个，入队即算在读；失败后先等 1 分钟，之后每次加倍到 15 分钟（codexhost 拒绝的 id 从 10 分钟起，最长 1 小时），每一步只记一行日志。Desktop 的委派树 20 秒内算新鲜，以它为准；Desktop 在前台时，树没变也每 10 秒左右重报一次。
- 委派继承：有前端在轮询时（最近 60 秒内调用过 `snapshot`），每 30 秒检查一次进行中主线的各个窗口，把没有主线、也没被移出过、仍在运行或等用户处理的子窗口挂到父窗口的主线上（`via: "delegation"`）。父子链按完整的委派关系向上查找，所以中间窗口已结束时，仍在工作的孙窗口也能继承。

偏题设置和切换展开设置来自 `settingsSchema`，后台用 `ctx.readSettings()` 读取，命令行直接读取同目录下的 `settings.json`。

### 4.6 主线胶囊（两端共用的界面）

- 挂在页面上的一个 Shadow DOM 节点里，样式不影响宿主页面。
- **默认位置**：标题栏里最宽的空白处。测量标题栏内可见的文字和控件（截断的标题只算露出的部分），空当扣除两侧各 10px 后至少 260px 时放进去，胶囊按空当宽度缩短、文字省略；放不下时放在标题栏下方、对话列居中。
- **拖动**：可以拖到任意位置，按界面分别记在 `localStorage`，以胶囊左边缘为准，内容变长时向右伸展；双击复位。胶囊带 `app-region: no-drag`，压在窗口拖动区域上也能点。
- **收起时**是一行胶囊：状态点、「主线：目标」、「正在做：…」、窗口数、展开箭头。偏题时状态点和边框变成琥珀色，并显示「偏离主线：…」。
- **展开后**是一张卡片：
  - 目标（可直接编辑）；
  - 已完成（最近 5 条，可展开全部）；
  - 正在做：本窗口在前，其他窗口带标题和实时状态，点击即跳转；
  - 支线待办（可标记完成或删除）；
  - 偏题提示条，带「记入支线」「改为主线」「忽略」三个按钮；
  - 头部的列表按钮展开「全部主线」：其他进行中的主线及其窗口，点击跳转，或把本窗口移过去；
  - 底部：「移出主线」「结束主线」（都要在 3 秒内再点一次确认），以及打开总览页的路径提示。
- **本窗口没有主线时**，胶囊只显示「＋ 主线」。展开后可以「设为主线」（目标默认取窗口标题，可修改），或从下拉列表「加入已有主线」。
- **切换窗口时**，如果新窗口有主线，卡片自动展开 3 秒，鼠标移入时保持展开（可在设置里关闭）。0.8 起：胶囊本身默认关闭（0.3.1 起，设置「对话标题栏也显示主线胶囊」），打开后切换到有进行中主线的对话时才自动展开 3 秒，这个展开没有单独的开关。
- 颜色根据宿主页面背景的亮度切换浅色或深色。文案提供中文和英文，按页面语言选择。
- 轮询：页面可见时每 2 秒调用一次 `snapshot`；页面隐藏时暂停，重新可见时立即刷新。后台不可用时，胶囊显示为灰色，并按指数退避重试，最长间隔 30 秒。

### 4.7 当前窗口的识别与跳转

| 界面 | 识别当前窗口 | 跳转 |
| --- | --- | --- |
| Codex Desktop | 页面上可见的 `[data-above-composer-conversation-id]` 属性；找不到时用 `sidebar.observeRows` 中带 `data-app-action-sidebar-thread-active="true"` 的行。 | `api.navigate.openThread(id)` |
| 自带窗口和 Web | 侧栏中带 `aria-current="page"` 的会话行：项目里的行是 `data-row-key="session:<id>"`，「最近」里的行是 `recent:<id>`；找不到时用未隐藏的 `[data-sidebar-right-session]`；侧栏收起时保留上一次的结果。 | 点击对应侧栏行；侧栏里没有这一行时，跳转到 `?session=<id>`。 |

两端都用 `MutationObserver` 监听相关属性，变化合并到 200 ms 后处理，另外每 1.5 秒复查一次。总览页在同一页面内派发 `codexhost-mainline:open-thread` 事件，由当前界面的入口完成跳转；Web 上没有入口响应时跳转到 `?session=<id>`。

诊断：两端入口在识别结果或胶囊位置变化时，把当前窗口、标题栏和胶囊位置报给后台（`diagnose`），后台每个界面最多每 4 秒写一行到 `backend.log`，用于排查位置和识别问题。0.8 起诊断默认关闭：只有在这个界面的开发者控制台里设置 `localStorage["codexhost-mainline:debug"] = "1"` 后，界面才量取自己（`describe()`）并上报，收藏的上报也一样；没有设置项。

### 4.8 主线总览页（0.10 起叫「第二大脑」）

- 进行中的主线：目标、已完成、各窗口及其正在做和状态、支线待办；可以编辑目标、合并到另一条主线、把窗口移到别的主线、结束。
- 合并：把主线 A 合并进 B 时，A 的已完成和支线待办按时间并入 B，A 的窗口全部改挂到 B，然后删除 A。
- 已结束的主线：折叠列出，可以重新打开或删除。删除主线时，它的窗口变回「没有主线」，但不标记为移出。
- Agent 协作：Claude Code 和 Codex 各一行，显示状态和「预览改动」「安装」「卸载」按钮。
- 偏题设置的快捷切换，写入同一份插件设置。

### 4.9 PR 与 Issue 索引（按编号找回对话）

**问题**：PR 和 issue 散落在不同对话里。维护者回复 #42 时，用户只知道编号，不知道它在哪个对话、当时要解决什么问题。

**已确认**：扫描全部历史对话；用 `gh` 自动提醒维护者回复（2026-11-23）。

- **索引文件**：`…/mainline/refs.json`，与 `state.json` 分开，用自己的锁。每条记录以 `owner/repo#编号` 为键，包含：类型（PR / issue）、链接、GitHub 标题和状态、出现过的位置（窗口、第几轮、谁提到的、那一轮用户的消息，截断到 200 字；每条最多 8 处，最早的一处是「来源」）、Agent 的说明、最近一次 GitHub 动态和用户是否看过。最多 2000 条，超出时丢弃最久没出现的。
- **扫描**：后台通过 codexhost 本机接口只读扫描。首次先翻完对话列表（`/v1/thread/list` 分页，约 5 页），再按更新时间倒序逐个读取，每个对话按 50 轮一批（`/v1/thread/read` 的 messages 视图），找出 `https://github.com/<owner>/<repo>/(pull|issues)/<n>` 链接。读取超时 20 秒，失败的对话放回队尾，最多试 3 次；中途重启时重新列出，已读过的自动跳过。之后每 60 秒只看最近更新的对话，从上次读到的轮次往后读；仍在进行的最后一轮下次重读。请求逐个发出，间隔 250 ms。
- **扫描（0.8 起）**：最近 10 分钟没人用插件界面时，最近更新的对话改为 10 分钟看一次。一次读取没找到页面看得到的变化（新链接、标题、项目、开头的请求）时，只把读到第几轮记在内存里，一轮结束（最多 1 分钟或 50 条）再一起写入，不再每读一个对话就重写 `refs.json`。对话记录只存工作目录的最后一级（启动时把旧记录改过来）和 codexhost 列出的 Agent（`harnessId`，完整列出时给旧记录补上）。每次完整列出对话后，忘掉 codexhost 已经没有、没有 PR 提到、也没有主线、最近消息或收藏的对话；列出的数量不到上次一半时一个都不忘。存下的请求和对话开头先遮掉密钥，旧版本存的在后台启动时补遮一次。启动时删掉旧版本留下的 `refs.before-*.json` 和 `state.before-*.json`。
- **当时的问题**：取那一轮用户消息里 `## My request:` 之后的原话；带附件但没有这个标记的消息去掉附件列表。
- **Agent 说明**：新命令 `mainline link <链接> "它解决什么问题"`，Agent 创建或提交 PR、issue 后运行；协作约定里加上这一条。`mainline find <编号|链接|关键词>` 打印对应窗口和当时的问题，用户和 Agent 都能用。
- **回复提醒**：后台每 3 分钟运行一次 `gh api notifications`（只读，不改 GitHub 上的已读状态；0.8 起最近 10 分钟没人用插件界面时改为 10 分钟一次，上次查询的时间另存在 `github-poll.json`，不再改写 `refs.json`）。已索引的 PR/issue 有新动态时记为未看。首次运行只为 GitHub 上仍未读的通知提醒，其余作为基线。`gh` 不可用时在总览页说明原因，搜索不受影响。设置项 `prAlerts` 可以关闭提醒。
- **标题与状态**：没有标题的条目用 `gh api repos/<repo>/issues/<n>` 补齐标题和状态（open / closed / merged），每轮最多 20 条，30 分钟内不重复查询。后来加上：被看到的 PR（悬停卡片、搜索、`mainline find`，总览页「PR 与 Issue」页签显示时最新 6 条）超过一分钟没查就再查。0.8 起：查到的标题和状态没变时，后台把这次查询记在内存里，`refs.json` 里的查询时间超过 10 分钟才写；命令行照旧每次都写。
- **界面**：
  - 有未看的动态时，每个窗口的胶囊左侧出现提醒（例如「#42 新回复」或「3 条新回复」）。点开后卡片顶部列出这些动态：编号、标题、来源窗口、当时的问题、「跳转」。
  - 打开某条动态的来源窗口后，这条提醒视为已看。
  - 卡片里有「本窗口的 PR 与 Issue」一节，头部的搜索按钮可以按编号、链接或关键词找回任意 PR/issue，并跳到来源窗口。
  - 总览页新增「PR 与 Issue」一节：搜索框、有新回复的在前、每条显示来源窗口和当时的问题，以及扫描进度和 GitHub 提醒状态。

## 5. 错误处理

- 后台未运行或调用失败：胶囊变灰并重试，总览页显示错误提示，不影响宿主界面。
- 命令行不在 codexhost 会话中：提示需要 `CODEXHOST_THREAD_ID`，或用 `--thread` 指定窗口。
- 锁等待超时：命令报错，提示稍后重试；hook 模式放弃记录 `lastPrompt`，但仍输出主线内容。
- 编号不存在、窗口没有主线时执行 `done` 等命令：给出明确的错误和下一步建议（例如先 `mainline new`）。0.8 起见 v2 设计 §7：开着模型凝练时不再让 Agent 手写主线，`doing`、`task`、`done "…"`、`spinoff` 直接从草稿建主线。
- 远程 Host 的窗口不处理，胶囊不显示。

## 6. 测试

- 单元测试（Vitest）：存储的读写、加锁、损坏恢复和上限；各项操作；协议文本在三种偏题设置和有无主线时的输出；命令行参数解析和在临时目录里的端到端运行；hook 的输出格式和静默失败；安装器在临时 HOME 下的安装、重复安装、更新和卸载；胶囊渲染；用 DOM 夹具测试两端的当前窗口识别。
- 构建检查：`desktop.js` 能作为严格模式函数体加载；各入口打包后不含动态 `import()` 和裸包名；体积在宿主限制内。
- 集成：先用隔离的数据目录试装，再装进用户的 codexhost 实机试用 Desktop 和自带窗口。

## 7. 第一版不做

- 不由插件新建窗口（建议用户自己新开，或让 Agent 委派）。
- 插件不读取完整对话记录，也不调用任何模型。
- 只内置 Claude Code 和 Codex 的协作安装；其他 Agent 可以手动使用命令行。
- 用户确认之前，不推送到 GitHub、不发布 Release、不向插件市场投稿。
